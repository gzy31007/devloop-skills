# loop-plan · 前置调研与边界收敛

在动手写代码前锁定可行性、技术路线、外部可观察行为与关键取舍。脚本文档路径遵循当前模式：自研模式读写根目录，客串模式读写 `.loop/`；脚本优先从 `loop-review` 技能目录拼接，CI 与夹具优先读 `DEVLOOP_KIT`。

## 零、前置调研（按需触发）

从零启动新项目、技术栈未定或涉及陌生外部接口时执行本节；边界清晰的小改动直接进入「一、收敛边界与原型比选」。

| 宿主能力 | 调研执行方式 |
| --- | --- |
| 支持子代理 | 派发 1 个（多路线并行时 2~3 个）只读调研子代理，仅回传浓缩证据简报 |
| 单会话宿主 | 在当前会话执行精简只读调研，输出同等结构简报 |

能通过文档、本机依赖或最小探针核实的事实优先查证。无联网环境在简报顶部注明「离线推演 · 待联网核实」。

| 简报必备项 | 内容要求 |
| --- | --- |
| 可行性结论 | 明确判断（可行 / 有条件可行 / 不可行），附官方文档、仓库链接与查证日期 |
| 推荐技术栈 | 结合目标场景、生态成熟度、兼容度与维护成本给出首选 |
| 候选路线对比 | 用表格对比 2~3 套路线的核心思路、优缺点、风险与工作量 |
| 未知项与探针 | 列出待验证前提及最小探针验证结果 |

## 一、收敛边界与原型比选

用一两句话明确本次目标与外部可观察验收条件，列清涉及模块、公开接口签名与数据形状（字段、类型、默认值、键顺序）。存在多条可行路线时各写最小原型隔离运行，按同一组指标（耗时、行数、复杂度、可读性）择优，指标相近选改动面更小的路线。

在 `DECISIONS.md` 中必须写明失败降级语义、并发/一致性边界与本版明确接受的局限，避免写审双方对未承诺边界产生歧义。

## 二、同步文档与交接

无需另造独立计划文件，直接写入对应文档与 `.loop/handoff.md`：

| 文档 | 更新规则 |
| --- | --- |
| `FEATURE_MAP.md`（客串在 `.loop/`） | 新项目按 `references/feature_map.template.md` 写 4 列（`版本 \| 功能 \| 入口 \| 验证`）；既有 3 列旧表沿用兼容 |
| `DECISIONS.md`（客串在 `.loop/`） | 按 `YYYY-MM-DD \| [active] \| 选择与理由（含失败语义、并发边界与本版局限） \| 放弃 \| 推翻触发条件` 追加；失效前提标记 `[superseded by ...]` |
| `.loop/handoff.md` | 编码前锁定本轮完整 `基线 SHA`（`git rev-parse HEAD`）与 `契约与边界摘要`，写入验收目标与待验假设 |

文档与交接基线锁定后进入 `/loop-build`。
