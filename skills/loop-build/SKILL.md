# loop-build · 写好代码

## 一、开分支

从约定的基线拉 `feat/<版本>-<主题>`，一个版本一个提交，父提交写清楚。主干与版本标签由发版流程处理。

## 二、源头防错底线（沉淀自实战复盘）

动手写业务代码前，以下高频坑默认从源头防住：
1. **文本与文件读写**：统一剥离 UTF-8 BOM（`utf-8-sig` / `replace(/^\uFEFF/, "")`），兼容 CRLF/LF，写盘优先采用「临时文件 + 原子重命名」，完整捕获解压与 I/O 异常并返回与正常路径同形的结果。
2. **入参前置拦截**：CLI 与 HTTP 共用的边界参数（路径、端口、下标、空标题）在绑定端口或写入磁盘前统一拦截，拒绝非法输入且保持原数据零改动。
3. **写操作幂等与防连点**：前端删除/提交按钮在请求期间加锁或禁用防双击；后端删除/修改优先按唯一稳定 ID 定位，避免按易漂移数组下标误删相邻数据。
4. **路径动态定位**：脚本与测试按自身文件位置动态推导根目录，避免写死依赖目录层数的 `..` 相对路径，确保在深层 worktree 或解包目录表现一致。

## 三、缺陷先红后绿与真实结果测试

1. **复现缺陷**：先写最小失败用例并确认红灯，再改根因，最后把用例并进回归套件；修完重跑确认同一用例转绿。
2. **真实结果优先**：优先写针对外部可观察结果（CLI 输出、HTTP 接口、真实落盘文件、浏览器交互）的验证，拒绝只 mock 内部函数凑覆盖率的无效单测。
3. **核心逻辑配脏输入属性测试**：触及解析器、状态机、编解码或规则计算时，配属性不变量测试（Python 用 `hypothesis`，TS/JS 用 `fast-check`），固定随机种子、打印样本数，并让生成器覆盖空值、BOM、脏行与边界极值。

## 四、自测与门禁

```bash
python -m pytest -q                                       # 或项目自带的测试与构建入口
python skills/loop-review/scripts/arch_gate.py --json .   # 架构门禁
```

服务、浏览器测试或占端口的长命令统一走 `reap_and_run.py`，跑完自动回收进程与端口：

```bash
python skills/loop-review/scripts/reap_and_run.py --cwd=. --timeout=600 python verify.py
```

## 五、写交接

`.loop/handoff.md` 按 `references/handoff.template.md` 填：目标、基线、候选 SHA、改动范围、自测命令与退出码、已知待验项、本版打回次数。打回一次就在末尾加一行，写清打回原因与修复方式。

## 六、交给审查

交接写完即停手，按当前 Agent 能力给唯一明确的下一步提示：

- **当前 Agent 支持子代理工具**（如 Antigravity / Claude Code / Codex / OpenCode）：明确告诉用户**直接在当前对话输入 `/loop-review`**（由其自动拉起独立只读子代理盲审），无需另开新对话。
- **当前 Agent 仅支持单会话**：明确提醒用户**新开一个干净对话再输入 `/loop-review`**。
