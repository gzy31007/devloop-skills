# loop-review 审查核对清单与故障注入参考

本文件供 `/loop-review` 按需查阅，细化多语言检查入口、Web 浏览器实测要点、形式化/属性检验核查、凑数单测识别与黑盒故障注入招数。

---

## 一、多语言真实结果与门禁对照

| 语言 / 栈 | 真实结果验收优先入口 | 类型与静态门禁 | 形式化 / 属性测试常用工具 |
| --- | --- | --- | --- |
| Python | 真实运行 CLI / HTTP 服务 / `verify.py` 端到端脚本 | `arch_gate.py --json .`、`ruff` / `mypy`（若项目配置） | `hypothesis`（固定 `@seed(...)` 或 `--hypothesis-seed`，打印样本数） |
| TypeScript / JavaScript | 真实构建产物（`build`）+ 启动服务/插件实测 + Playwright/E2E | `arch_gate.py --json .`、`tsc --noEmit`、项目原生 Lint | `fast-check`（固定 `seed` 与 `numRuns`，打印实际运行次数） |

### 自研模式 vs 客串模式
- **自研模式（Own Repo）**：以 `.loop/config.json`、`FEATURE_MAP.md`、`DECISIONS.md` 与 `arch_gate.py` 为硬门禁。
- **客串模式（External Repo）**：以上游仓库自带的构建、Lint、Typecheck 与测试命令为硬门禁；本地辅助规则存在 `~/.devloop/projects/<repo-id>/`，审查时额外核查 `git status` 确保未污染上游 `.gitignore` 与工作树。

## 二、揪出「凑数单测」自检项

遇到以下情况，在裁决单第 1 节明确点出；若导致核心结果缺乏真实验证，直接升级为阻断打回：
1. **过度 Mock 内部实现**：把数据库、文件系统、HTTP、核心依赖全 mock 成写死返回值，测试只证明“mock 被调了一次”。
2. **断言过弱或恒等**：只断言 `result !== undefined`、`status === 200` 却完全不校验关键字段或实际落盘内容。
3. **测试配合代码改弱**：查看 `git diff`，发现本轮为了过测试删掉了旧断言、扩大了容差或把失败用例标成 `skip`。
4. **只测快乐路径**：完全没有异常输入、边界值或缺陷回归用例。

## 三、Web 项目浏览器实测细项

启动本地服务前优先使用 `reap_and_run.py` 或确保测完终止进程并释放端口：
1. **首屏与加载**：打开目标页面，确认无白屏、无未捕获 Console Error、无预期外 4xx/5xx 请求。
2. **核心交互链路**：按 `handoff` 验收口径完整点一遍（输入表单、提交、切换状态、刷新页面确认持久化或状态正确）。
3. **异常与边界操作**：快速连点/双击删除与提交、输入空值/超长中文/特殊符号、加载带 UTF-8 BOM 或脏行的文件、断网或非法参数（若适用），观察是否优雅降级、无崩溃、且页面展示与磁盘落盘字节一致无静默丢数据。
4. **可视与可点检查**：确认核心按钮、弹窗、导航栏在常规桌面视口（以及涉及移动端时的窄视口）下无严重遮挡或溢出导致点不到。
5. **证据留存**：在裁决单里写清访问的 URL、操作步骤、Console/Network 观测结果（有截图或 DOM 快照则注明位置）。

## 四、形式化 / 属性不变量检验核查

以下模块属于**必查适用范围**：
- 状态机流转（订单、审批、任务生命周期、熔断/重试计数）
- 解析器 / 序列化 / 编解码 / 格式化（JSON、Markdown、配置、协议报文）
- 规则引擎 / 金额与数量计算 / 权限判定 / 过滤排序算法
- 幂等与往返不变量（`decode(encode(x)) == x`、重复执行结果一致、排序后元素守恒）

核查要求：
- 必须能看到**明确的不变量断言**，确认使用了固定随机种子并输出实际样本数量（如 `100 examples`）。
- 必须核查**生成器输入域是否覆盖真实脏输入与边界值**（如 UTF-8 BOM、空文本、CRLF/LF、异常字符、越界下标），防止干净生成器制造假安全感。
- 仅手写 2~3 个固定样例无法替代属性测试；核心算法/状态机缺失属性检验直接归入阻断打回。

## 五、黑盒故障注入常用招数（按需挑 2~3 项实测）

1. **空与缺失**：空字符串、空数组、缺必填字段、目标目录/文件缺失。
2. **极值与越界**：`0`、负数、超大数值、超长文本、分页越界、非法端口或路径穿越（`../`）；核查 CLI 与 HTTP 共用参数是否在绑定端口前统一拦截且异常返回结构与正常路径同形。
3. **损坏与脏数据**：截断的 JSON/压缩包、UTF-8 BOM（`utf-8-sig`）、中英文混排与换行符差异（CRLF/LF）。
4. **重复与中断**：同一写入/删除操作双击或连跑两次检验幂等性；中途失败后检查是否留下脏文件、锁文件或僵尸进程。
5. **环境差异**：从非项目根目录或深层 worktree 执行 CLI 与测试命令、路径含空格或中文，核查脚本与测试是否动态定位根目录、未写死 `..` 目录层数。
