# loop-review 写审同源核对清单与故障注入参考

供 `/loop-build` 编码前圈定高风险项及自检，与 `/loop-review` 盲审打穿核验共用，统一多语言门禁、寻址键审计、浏览器与持久化状态、属性不变量及故障注入标准。

## 一、多语言验收与门禁

| 语言 / 栈 | 真实结果入口 | 静态门禁 | 属性检验工具 |
| --- | --- | --- | --- |
| Python | CLI / HTTP 服务 / 端到端验证脚本 | `arch_gate.py --json .`、`ruff` / `mypy` | `hypothesis`（固定 `@seed`，打印样本数） |
| TypeScript / JavaScript | 真实构建产物 + 启动服务 + Playwright/E2E | `arch_gate.py --json .`、`tsc --noEmit`、原生 Lint | `fast-check`（固定 `seed` 与 `numRuns`，打印次数） |

| 接入模式 | 门禁与文档基线 |
| --- | --- |
| 自研（`own`） | `.loop/config.json`、根目录 `FEATURE_MAP.md` 与 `DECISIONS.md`、`arch_gate.py` |
| 客串（`external`） | 上游原生构建、Lint、Typecheck 与测试；本地辅助配置存路径哈希隔离的影子目录，同时核查 `git status` 确认上游工作树零污染 |

## 二、寻址键审计与凑数单测排查

逐个写接口登记资源定位键，确认同一资源的增删改查保持单一寻址键类型。若同一资源同时出现数组下标与稳定 ID，立即注入 stale-index 场景（先删前项再以旧下标改后项）。

| 排查项 | 异常特征 | 处理 |
| --- | --- | --- |
| 过度 Mock | 数据库、文件系统或 HTTP 全部写死返回值，仅验证调用次数 | 指出并核查真实结果覆盖 |
| 弱断言或恒等断言 | 仅断 `status === 200` 或非空，省略关键字段与落盘校验 | 补齐结果断言或升级阻断 |
| 削弱原测试 | 差异中删除原有断言、放宽容差或跳过失败用例 | 直接阻断打回 |
| 缺失异常路径 | 仅覆盖正常输入，缺少空值、越界与回归用例 | 补充故障注入核验 |

## 三、浏览器与持久化状态

启动本地服务统一通过 `reap_and_run.py` 托管进程与端口。Web 与客户端改动按交互及存储入口选用以下必验基线：

| 核查项 | 适用条件 | 合格标准 |
| --- | --- | --- |
| 首屏加载与主链路 | 所有 Web 页面改动 | 无白屏、无未捕获 Console Error、无预期外 4xx/5xx，核心表单与状态切换生效 |
| 快速连点与幂等防重 | 存在删除、提交或写操作按钮 | 请求期间防重或后端按稳定 ID 幂等处理，相邻数据零误删 |
| 合法值单真源往返 | 存在表单控件、枚举配置或持久化编解码 | 控件元信息与解析校验共用定义域，全量合法值经保存与重载保持一致 |
| 存储拒访与配额超限 | 依赖 `localStorage`、IndexedDB 或文件持久化 | 模拟拒访或超限时失败回滚，输出可读错误，已有状态零静默丢失 |
| 对称路径零未捕获异常 | 存在新建、编辑、重置、删除等交互入口 | 兄弟控件、取消分支与对称操作零未捕获异常及未处理 Promise Rejection |
| 多视图与存储终态一致 | 状态联动列表、统计、弹窗或服务端存储 | 变更后各视图渲染与持久化终态一致，失败后重试可恢复 |
| 视口可视与可点 | 涉及布局、弹窗或表单 | 常规桌面视口及移动端窄视口下核心控件无遮挡溢出 |

## 四、属性不变量核查

适用范围：状态机流转、解析器、序列化与编解码、规则计算、权限判定、幂等与往返不变量（`decode(encode(x)) == x`）。

| 核查项 | 合格标准 |
| --- | --- |
| 可复现执行 | 输出固定随机种子与实际样本数 |
| 脏输入域覆盖 | 生成器包含空值、UTF-8 BOM、CRLF/LF、非结构行、异常字符与越界值 |
| 适用性留痕 | 涉及上述模块时缺失或失败即阻断；纯文案或纯样式注明不适用及理由 |

## 五、源头防错与通用故障注入配方

编码阶段结合改动领域圈定高风险项并落实防错，交审与盲审按需选取以下配方构造真实坏场景：

| 配方 | 源头防错与构造方式 | 预期行为 |
| --- | --- | --- |
| BOM / CRLF 与原子写盘 | 读取统一剥离 UTF-8 BOM 并兼容 CRLF/LF，写盘用临时文件加原子重命名并捕获解压/IO 异常；注入 BOM + CRLF + 非结构行测试 | 首行首列不丢，异常返回同形结构，原文件零半截损坏 |
| 入参前置拦截与忽略规则 | CLI/HTTP 绑定或写盘前校验空值、负数、非法端口与 `../`；运行期生成文件写入 `.gitignore` 与 `generated_paths` | 前置返回可读错误且原数据零改动，生成文件零跟踪 |
| 幂等防连点与统一寻址键 | 写按钮加在途防重且增删改查共用唯一稳定键；注入同 ID 连点与 stale-index 坏序请求 | 幂等或稳定提示生效，相邻数据零误伤 |
| 并发与一致性契约 | 按 `DECISIONS.md` 获准的一致性契约，分别构造延迟回执乱序与真实交错并发写入 | 严格满足已批准的一致性契约与数据保护要求，无静默丢数或残留临时文件 |
| 路径动态定位 | 按 `__file__` 或 `import.meta.url` 动态推导项目根；在异目录、含空格/中文路径运行 CLI 与测试 | 路径推导稳定生效，零固定层级相对路径失败 |

## 六、写审边界与落盘核验

| 核查项 | 要求 |
| --- | --- |
| 预检与工作树洁净 | 审查前运行 `devloop_ops.py preflight` 通过；落盘前后 `git status --porcelain` 为空，源码、测试、配置与 `.loop/handoff.md` 零改动 |
| 落盘通道 | 裁决正文经 UTF-8 stdin 或仓库外 `--body-file` 传入 `devloop_ops.py review-record` |
| 跨工作区审查 | 隔离 worktree 审查时，通过 `--state-root`、`--docs-root` 与 `--branch` 关联主工作区状态和文档 |
