# loop-review · 实锤独立审查

像 Breaker 一样带着「试着把它打穿」的心态审查：全程只读、亲自实跑、只认现场原始证据。严禁修改业务代码与测试代码，严禁轻信 `.loop/handoff.md` 里的自测宣称。

---

## 一、写审单次隔离（防套娃）

先判断当前对话是否参与过本轮编码，只做一次上下文隔离：

1. **当前对话刚写过本轮代码**（上下文已包含编码过程）：
   - **支持子代理工具**：拉起 1 个只读隔离子代理做独立盲审。
   - **仅支持单会话**：立即停手，提示用户**新开一个干净对话再输入 `/loop-review`**。
2. **当前对话本身就是干净的新对话**（本会话未参与本轮编码与改文件）：
   - 直接在当前对话内按只读原则独立完成审查，无需再额外拉起子代理。

### 子代理盲审装包规范

派发只读子代理时，提示词**只允许传入客观材料**：
- `.loop/handoff.md`（目标、基线/候选 SHA、改动范围、自测入口）
- `git diff <基线>..<候选>`（或当前分支相对主干的完整 diff）
- `FEATURE_MAP.md` 与 `DECISIONS.md`
- `.loop/config.json`（若为客串模式则读取 `~/.devloop/projects/<repo-id>/` 下配置）
- 本技能全文与 `references/review-checklist.md`

**严禁传入**本轮编码时的辩解、主观推测或「已经测过了」之类的引导词。

## 二、六步实锤审查剧本

按顺序执行，每一步保留可复现命令与原始输出摘录（完整多语言细项与故障注入招数见 `references/review-checklist.md`）：

### Step 1：核对范围、契约与文档前提
1. 对照 `.loop/handoff.md` 与 `git diff --stat`，核查**爆炸半径**：改动文件是否全部落在计划边界内，有无夹带无关修改、临时垃圾或越界改动。
2. 逐条对照 `FEATURE_MAP.md` 与本次验收目标，确认没有遗漏任何外部可观察行为。
3. 核验 `DECISIONS.md` 中相关条目在当前代码现实下是否仍成立；前提已失效的条目要求在返工时标为 `[superseded by ...]`。

### Step 2：亲自重跑真实结果验收（重结果、揪凑数）
1. 亲自执行项目端到端验收命令（CLI 跑真实命令验标准输出/退出码/落盘产物；API 跑真实请求验状态码与响应体；插件/库验真实构建产物与加载行为），用 `reap_and_run.py` 托管占端口或长时进程。
2. **排查凑数单测**：检查本轮新增或修改的测试，揪出以下反模式并直接标出：
   - 仅 mock 内部函数/私有方法、完全脱离真实运行结果；
   - 断言恒等式或空转无校验；
   - 通过删减或放宽原有断言来强行凑绿灯。
3. **缺陷回归核验**：若本轮包含缺陷修复，确认已补入最小回归用例，且能证明修前复现、修后转绿。

### Step 3：Web 项目浏览器实测闭环
只要本轮改动涉及前端页面、组件、样式、路由或 HTTP UI，必须执行真实浏览器验收：
1. 通过 `reap_and_run.py` 启动本地开发或预览服务，测完自动回收进程与端口。
2. 使用当前环境可用的浏览器工具（内置浏览器 / Playwright / Chrome DevTools）打开真实页面，按用户视角走完本轮 `handoff` 的核心操作路径与关键回归路径。
3. **4 条默认阻断红线**（命中任意一条即阻断打回）：
   - 控制台出现未捕获 JS Error、Unhandled Rejection 或页面白屏/渲染崩溃；
   - 页面触发预期之外的 4xx / 5xx 网络请求失败；
   - 核心交互点击/提交无响应，或关键元素缺失、状态错乱；
   - 严重布局遮挡或溢出，导致核心按钮/表单无法点击操作。
4. **权限与环境兜底**：
   - **只读子代理无浏览器权限**：子代理先完成代码、门禁、真实命令与属性检验盲审，并在报告里输出一份明确的**「浏览器必验清单」**（含启动命令、URL、操作步骤与预期结果）；主会话随后严格照单开浏览器逐项实测，并把实测证据补入最终裁决。
   - **当前环境完全无浏览器工具**：严禁静默当成已通过，必须在报告结论前显式标注**「待人工浏览器实测」**，并给出本地启动命令与必测路径清单。

### Step 4：形式化 / 属性不变量检验核查（必须显性留痕）
检查本轮改动是否触及**核心状态机、解析器、序列化/编解码、规则/计费/权限计算或关键数据流转**：
- **若触及**：必须核验存在对应的属性/不变量测试（Python 如 `hypothesis`，TS/JS 如 `fast-check`），亲自重跑并记录**固定随机种子 + 实际样本数**；缺失或失败直接归入阻断打回。
- **若未触及**（如纯文案、纯样式、简单胶水层）：在报告对应栏目明确写明「不适用」并附一句具体理由。

### Step 5：黑盒破坏性测试与机械门禁
1. **黑盒故障注入**：参照 `references/review-checklist.md`，针对本轮核心入口主动构造至少 2~3 个坏场景试探（空输入、边界极值、非法格式、损坏文件/JSON、特殊字符/中文编码、重复提交或并发中断），把打穿的现场记入复现清单。
2. **机械门禁**：
   - **自研模式**：跑 `python skills/loop-review/scripts/arch_gate.py --json .`（按 `.loop/config.json` 配置），核查文件行数、函数复杂度、循环依赖与零错误退出。
   - **客串模式（外部仓库）**：以上游仓库自带 Lint / Typecheck / Test / CI 为准；若本地配置了辅助门禁，结果仅作参考且确保工作树与 `.gitignore` 零污染。

### Step 6：节奏、熔断与裁决分级
- **每 3 个版本**（v0.3 / v0.6 / v0.9…）：核查是否已完成外部行为零变更的减法重构检查点，并留存行为等价证据。
- **打回计数与熔断**：读取 `.loop/handoff.md` 累计打回次数——单版有效打回**满 2 次**标记「需跨模型抽检」，**满 3 次**立即熔断并保留现场等待用户裁决。
- **两级结论口径**：
  - **阻断打回**：可复现运行报错、旧功能退化、验收目标漏项、Web 四条红线命中、核心逻辑缺形式化/属性检验、凑数单测掩盖真问题、门禁红灯、越界改动——**每条必须附一键复现命令与原始报错**。
  - **非阻塞建议**：命名、排版审美、可延后重构的局部细节——仅记录，不拦放行。

## 四、附带脚本

`scripts/` 下三个零外部依赖的标准库脚本，跨平台可用：

| 脚本 | 用途 |
| --- | --- |
| `arch_gate.py` | Python + TS/JS 行数、复杂度、循环依赖门禁，`--json` 输出 |
| `reap_and_run.py` | 进程树与端口回收，Windows 与 POSIX 各走各的分支 |
| `verify_scripts.py` | 本套件脚本的隔离自测，临时目录用完即删 |
