# agent-docs · 面向 Agent 的文档写作规范

面向 Coding Agent 的文档服务于检索、解析与执行。每份文档保持低噪声、高信息密度与可核验性。

## 适用范围

| 文件类型 | 示例 |
| --- | --- |
| 技能文件 | `skills/*/SKILL.md`、`references/*.md` |
| 项目文档 | `README.md`、`docs/*.md`、`FEATURE_MAP.md`、`DECISIONS.md` |
| 代码与测试说明 | 模块 docstring、测试函数名、测试标题、断言说明 |

## 核心风格规范

| 维度 | 写作要求 | 正例 | 反例 |
| --- | --- | --- | --- |
| 段落 | 拆小段，每段一事，求精简 | `默认端口为 18700。` | 把配置、背景与异常处理塞进同一大段 |
| 结构 | 表格优先于列表 | 用二维表展示参数、默认值与行为 | 用多层嵌套无序列表堆叠规则 |
| 表达 | 多真实代码，少比喻 | 直接贴出可运行命令或函数签名 | 用“高速公路”“守门员”类比模块职责 |
| 时态 | 只写当前状态；避写“不再/原先/旧版/已废弃/实测/已经”等提旧事的词 | `入口读取 UTF-8 编码并自动剥离 BOM。` | `新版不再受 BOM 影响，原先旧版已经废弃。` |
| 用词 | 用“适用范围”替代“口径”；省去“红线”“踩坑”类叙事 | `适用范围：Python 与 TS/JS 源码。` | `统一口径，以下三条红线防止踩坑。` |
| 符号 | 禁用 emoji | `PASS`、`FAIL`、`[active]` | 使用勾选、火焰、火箭等表情符号 |
| 事实 | 代码、数字、结论取自源码，严禁编造 | 读完源码后写明真实命令与阈值 | 凭记忆写参数名或估算行数上限 |

## 正文结构模板

编写 `SKILL.md` 或 `docs/*.md` 时按以下顺序组织，缺省时省略空节：

| 章节 | 写法 |
| --- | --- |
| 标题与定位 | 一句话说明当前文件的职责与触发场景 |
| 适用范围与前置条件 | 用表格列明输入、目录与依赖 |
| 执行步骤与规则 | 用表格或短代码块给出可执行命令与判定条件 |
| 输出契约 | 用真实代码片段展示目录结构、CLI 输出或返回字段 |

## 真实代码优先示例

展示命令或接口时，直接给出当前源码中存在的调用方式：

```bash
python skills/loop-review/scripts/arch_gate.py --json .
```

测试标题直接陈述输入条件与可观察结果：

```python
def test_bom_csv_preserves_first_column_header():
    ...
```

## 交付前自检

| 检查项 | 通过标准 |
| --- | --- |
| 事实核对 | 路径、命令、参数、数字与当前源码完全一致 |
| 时态清理 | 仅描述当前有效行为，无历史对比叙述 |
| 结构压缩 | 并列项优先采用表格，无超过 4 行的长段落 |
| 符号与措辞 | 零 emoji，无“口径”“红线”“踩坑”及无意义比喻 |
